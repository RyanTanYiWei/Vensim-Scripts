# Vensim Script Builder

A browser-only Vensim script builder. Open `index.html` or publish the repository root with GitHub Pages; no build or server is required. Clipboard access requires a secure context such as GitHub Pages or localhost. Files are read locally and are not uploaded.

Add single runs, sensitivity runs, exports, or custom commands; reorder using the six-dot drag handle, or focus it and use the up and down arrow keys. Use the duplicate icon to copy a step immediately below it. Copies retain their settings, including run names; rename copied runs to avoid overwriting the original run's results. Run names and optional additional input filenames are editable in the header. A single run's header lets you edit one variable and value; add more in the expanded step. When multiple rows are present, the header shows the count of entries with both a variable name and value, excluding changes from an additional input file. Select a step's header to expand its fields; new Export CSV steps start expanded, while other new steps start collapsed. Downloads use UTF-8 and Windows line endings.

Importing a `.cmd` groups recognized run sequences and supported CSV exports into editable steps. Blank and whitespace-only lines are omitted from the workflow and regenerated script. Unsupported or ambiguous commands remain individual editable lines, in order. Recognized exports must refer to exactly one preceding run and use the builder's supported options; other exports remain raw. Unchanged recognized steps retain their original command text, and imported runs without `SIMULATE>BASED|` continue without a reset even after editing. A sensitivity control file is referenced by name; the `.cmd` alone cannot reveal whether it uses a sample table. Review imported scripts before running.

Drop a UTF-8 `.mdl` file on the model control beside the Workflow heading, or choose it with **.mdl**. Open **Model Context** or **Model loaded** to view details or remove the model; issues are shown automatically. The file stays in the browser and does not add a load-model command to the script. Numeric, changeable constants and their original values are suggested when entering variables; values already entered in a run are never replaced. The parser supports quoted names, explicit subscript elements, lists with one explicit range, and a single value shared across multiple ranges. Multidimensional lists, external spreadsheet constants, and other definitions that cannot be safely resolved are not offered as selectable constants; the model panel lists unresolved numeric or external definitions. Unchangeable (`==`) constants and equations are excluded. Check the original model when a constant is not listed.

Numeric `INITIAL TIME` and `FINAL TIME` become defaults for single-run `VDF2CSV` exports, including existing exports whose times have not been edited. Use a single-run row's **Apply to All** button to copy its Start and End to every selected single-run row in that export step, including blank values. Applied times are treated as manual edits and do not change with later model context; new rows retain their own defaults. The export interval defaults to 1; leave it blank to use Vensim's SAVEPER. Manually edited times are preserved when changing or removing the model. Time units are shown for reference. Sensitivity exports use `SENS2FILE`, which has no equivalent interval or start/end options and are not affected by Apply to All. Imported raw commands are never modified. The parser does not evaluate expressions or read external files; missing or non-numeric time settings must be entered manually.

Each newly created run resets model changes with `SIMULATE>BASED|`, then applies the optional Additional Inputs filename using `READCIN` and any entered variables before running. Enter the Additional Inputs filename without its extension; the builder adds `.csv`. The file is not imported or converted. Vensim documents `READCIN` as reading a `.cin` change file, so verify that the contents are compatible with your Vensim version; changing an extension alone does not convert a file. Newly created runs overwrite existing results without prompting.

For sensitivity runs, enter the `.vsc` control filename and `.lst` sensitivity save-list filename without their extensions; the builder adds the suffixes. To use a manual sample table instead, select the `.txt` option and enter the sample-table filename without its extension; the builder adds `.txt`. Enter the generated control-file name without `.vsc` and download it. Put the control file at the path specified in the script and put the tab-delimited UTF-8 sample table where Vensim can find it. The first row must contain model constant names; each subsequent row contains sample values. See [Vensim's sensitivity control format](https://www.vensim.com/documentation/sensitivitycontrol.html).

Each new export step initially includes all preceding runs. If there are none, it starts empty; add runs to the workflow and click **Export All** to include them. **Export All** adds every preceding run without removing existing selections or edited filenames; click it again to add newly preceding runs. **Clear All** removes that export step's selections, and **Add Run** adds an individual selection. Each row defaults to `<run name>.vdfx` and `<run name>.csv`; the CSV name can be changed. Renaming a run updates its automatic filename. Single-run exports use `VDF2CSV`; sensitivity exports use `SENS2FILE` with the comma option for CSV. Imported simple `RUNNAME` / `RUN` commands are also available for selection. Check file paths, edition support, and all generated commands before running: this tool cannot execute Vensim or validate a model. Refer to the [supported commands](https://www.vensim.com/documentation/ref_cmd_supported.html).

Run the tests with `node --test tests\script.test.js tests\model.test.js`.
